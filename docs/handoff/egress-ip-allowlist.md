## 1. 한 줄 요약

**서버가 외부로 나갈 때의 출발지 IP가 곧 바뀝니다.** 그 IP를 외부 업체 시스템에
등록해 두신 연동이 있는지 확인이 필요합니다. **§3 의 질문 4개에 답만 주시면 됩니다.**

## 2. 배경 — 무엇이 바뀌나

현재 private 서브넷(Prod/Dev API)의 인터넷 아웃바운드는 **모니터링 EC2 한 대가
NAT 역할을 겸직**해서 처리합니다. 이 노드가 죽으면 관측·아웃바운드·개발자 접근이
동시에 끊기는 구조라, **관리형 NAT Gateway 로 분리**합니다.

전환하면 **밖에서 보는 우리 서버의 IP가 새 IP로 바뀝니다.** 기존 IP를 그대로 물려받는
방법은 없습니다 (현재 IP 가 고정 IP(EIP)가 아니라 자동 할당 IP 라 이전이 불가능합니다).

> 참고로 자동 할당 IP 는 인스턴스를 정지·기동하면 바뀝니다. 즉 **지금 IP 도 원래
> 영구적으로 보장되던 값이 아닙니다.** 그동안 문제가 없었다면 허용목록 의존이
> 없을 가능성이 높지만, 결제 경로라 추정으로 넘기지 않고 확인하려는 것입니다.

### ⚠️ 혼동하기 쉬운 부분 — 방향이 중요합니다

| 방향 | 이번 변경의 영향 |
|---|---|
| **아웃바운드** — **우리가 나갈 때의 IP** 를 상대 시스템에 등록해 둔 것 | **이것이 영향을 받습니다. 질문 대상입니다** |
| 인바운드 — 상대의 콜백/웹훅이 우리 쪽으로 들어오는 것 | **영향 없습니다.** 들어오는 경로(ALB)는 그대로입니다 |

## 3. 질문 4개

| # | 질문 | 답변 형태 |
|---|---|---|
| **Q1** | **외부로 나갈 때의 출발지 IP 를 상대 시스템에 등록해 둔 연동이 있습니까?** 특히 **페이플**. 그 외 알림톡/SMS 발송사, 메일 발송, 기타 계약 기반 외부 API 도 포함해 주세요 | 있음/없음 + 있다면 **어느 업체·어느 화면에 등록**했는지 |
| **Q2** | **서버에서 외부로 나가는 연동을 전부 알려주실 수 있습니까?** (허용목록 여부와 무관하게) | 대상 목록 (예: 페이플 승인 API, S3, 알림톡 …) |
| **Q3** | **결제 승인 요청이 "연결 끊김/타임아웃"으로 실패했을 때 복구 경로가 있습니까?** 재시도, 승인 상태 재조회, 멱등키 재사용 등 | 있음/없음 + 동작 설명 |
| **Q4** | **외부 호출에 커넥션 풀(keep-alive)과 재시도를 쓰십니까?** | 사용 여부 (라이브러리 이름이면 충분합니다) |

### 각 질문이 왜 필요한지

- **Q1** — "있음"이면 이건 순간 장애가 아니라 **등록 전까지 계속되는 결제 장애**입니다.
  이 경우 새 IP 를 **미리 발급해 전달드리고, 업체 등록이 끝난 뒤에** 전환합니다.
- **Q2** — 전환 시 영향 범위를 특정하기 위해서입니다. 인프라 쪽에서는 어디로 나가는지
  알 수 없습니다.
- **Q3** — 전환 순간 **진행 중이던 연결은 모두 끊깁니다.** 하필 그때 승인 요청이
  나가 있었다면 "앱은 실패로 알지만 PG 는 승인됨"이 될 수 있습니다. 복구 경로가 있으면
  작업 시간대 선택이 훨씬 자유로워집니다.
- **Q4** — 풀에 남아 있던 유휴 커넥션은 전환 후 **살아 있는 것처럼 보이지만 실제로는
  끊긴 상태**가 됩니다. 재시도가 있으면 흡수되고, 없으면 전환 직후 몇 건이 5xx 로 나갑니다.

---

## 4. 답변에 따라 저희가 하는 일

| 답변 | 조치 |
|---|---|
| Q1 = 없음 | 저트래픽·무배포 시간대에 그대로 전환 (작업 1시간) |
| Q1 = 있음 | 새 고정 IP 를 먼저 발급해 전달 → **업체 등록 확인 후** 전환 |
| Q3/Q4 = 재시도 없음 | 작업 시간대를 더 보수적으로 잡고, 전환 직후 결제 지표를 집중 관찰 |

**전환 자체로 서비스가 멈추지는 않습니다.** ALB 로 들어오는 요청 처리, Redis·DB 접근은
영향이 없습니다. 끊기는 것은 **전환 순간 진행 중이던 외부 나가는 연결**뿐입니다.
